# Application Icons

## Purpose

Application and tray icons for the Tauri desktop client (taskbar, dock, window chrome, installers, system tray).

## Layout

| Path | Purpose |
|------|---------|
| `source/app-icon.png` | **Source of truth** for the app icon (square, >= 1024 px) |
| `source/tray-icon.png` | **Source of truth** for the tray icon (simplified, readable at 16-32 px) |
| `icon.png`, `32x32.png`, `64x64.png`, `128x128.png`, `128x128@2x.png` | Generated by `tauri icon` (Linux bundles, window icon) |
| `icon.icns` | Generated, macOS bundle icon |
| `icon.ico` | Generated, Windows icon (16-256 px entries) |
| `tray/32x32.png`, `tray/64x64.png` | Generated from `source/tray-icon.png`; `tray/64x64.png` is embedded in `src/tray.rs` |

Everything except `source/` and this file is generated. Do not edit generated files by hand.

## Regenerating / swapping the artwork

Overwrite the two files in `source/`, then from `client/`:

```bash
bun run icons
```

(`client/scripts/generate-icons.mjs`: runs `bunx tauri icon` and keeps only the files `tauri.conf.json` references, resizes the tray icon with sharp, writes `client/public/favicon.ico` + `apple-touch-icon.png` and the Android launcher icons from the app icon.)

The guard test `client/scripts/__tests__/app-icons.test.ts` fails on placeholder (1x1, empty, stub) icons.

## Notes

- Windows-Store/MSIX `Square*Logo.png` files are not generated: no bundle target (`nsis`) uses them.
- Android launcher icons (`mobile/android/app/src/main/res/mipmap-*`, adaptive icon on `#2F3744`) are generated from `source/app-icon.png` by the same script.
- Prompts for the current artwork: `docs/developer-guide/design/image-prompts.md` (App and Tray Icons).
