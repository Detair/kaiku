## What is already true (no further work)

- **CI is green** across all workflows; the Security Audit no longer fails;
  every advisory exception is dated and justified.
- **Desktop client** has connection metrics, output-device selection,
  reconnect-safe unreads, a system tray, and **signed auto-update** via
  GitHub Releases.
- **Reliability is enforced in CI**, not just documented: tenancy/isolation
  regression tests, bundle-size + server-latency budgets, and a server-side
  diagnostics endpoint.
- **Operators have runbooks**: backup/restore, upgrade playbook with a
  preflight script, and an ops index — and a fresh VPS can be rebuilt from
  the repo (the previously-missing RustFS compose service was added).
- **Voice is sovereign by default** on self-hosted nodes (STUN points at the
  operator's coturn, not Google).

## Remaining engineering before v1.0

These are buildable without a product decision:

1. **Operator backup drill** (Goal 4 tail) — one documented restore drill on
   the live VPS. Operator-run; ~20 min. (`docs/ops/backup-restore-runbook.md`)
2. **Android beta** — ship the 5 blocker features (markdown, attachment
   display, unread indicators, DM UI, reaction picker) from the milestone in
   `roadmap.md`, add an instrumented UI smoke suite, one week of daily use.
3. **Release dry-run** — tag a `v1.0.0-rc`, confirm the signed desktop
   artifacts and `latest.json` updater manifest publish, and that an older
   build offers the update. (First real exercise of the auto-update pipeline.)
4. **Back up the Tauri updater signing key** (`~/.tauri/kaiku.key`) — losing
   it permanently breaks auto-update for installed clients.

## Product decisions (decided by maintainer, 2026-07-04)

v1.0 is scoped as **self-hosted, desktop + Android beta, English-only**:

- **i18n**: v1.0 ships **English-only**, documented as a known limitation.
  An i18n framework and string extraction are a post-1.0 roadmap item.
- **iOS**: v1.0 is **Android-only** on mobile (public beta). An iOS client
  is a post-1.0 roadmap item.
- **SaaS / billing**: v1.0 is **self-hosted-only**, matching the project's
  sovereignty thesis. The Stripe/billing track (Goal 6 item 5) stays
  unstarted and moves to a post-1.0 track; do not build speculatively.

With these recorded, the v1.0 gate reduces to the engineering remainder
above (Android beta rollout, operator drill, release dry-run, key backup).
