# v1.2 E2: voice messages and 1:1 video calls Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Record, send and play voice messages on desktop, web, the full Android app and Kaiku Einfach; add 1:1 video to DM calls on all four clients (camera on/off, front/back on Android, self-view, remote video full screen).

**Architecture:** A voice message is an ordinary message attachment with a voice flag, duration and waveform, uploaded through the existing `POST /api/messages/channel/{id}/upload`. The canonical format is **WebM/Opus**; recorders that cannot write it upload MP4/AAC, and (only if the spike says so) the server adds a WebM/Opus playback variant. Desktop records natively (cpal → libopus → a small WebM writer in a new shared crate), web uses `MediaRecorder`, Android uses `MediaRecorder` and plays with `MediaPlayer`. Video reuses the voice-room webcam path that guild voice channels already have (`VoiceWebcamStart`, `WebcamButton`, `VoiceTile`, `TauriVideoFrame`); the server marks DM calls as video-capable and refuses video outside 1:1 rooms. Android adds Camera2 capture through stream-webrtc-android.

**Tech Stack:** Rust (axum server, Tauri 2 native audio with cpal 0.17 + `opus` 0.3), Solid.js, Kotlin/Compose with stream-webrtc-android 1.3.0; platform `MediaRecorder`/`MediaPlayer`.

**Spec:** `docs/superpowers/specs/2026-11-02-phone-key-login-and-simple-app-design.md` (Decision 4; Part A "1:1 video and voice messages"). Package cut (coordinator's working notes, 2026-11-03): E2 in 2.2, hotspots 2.4, K16.

**Depends on E1:** `CallController`, `CallApi`, `InCallScreen`/`InCallViewModel`, `IncomingCallScreen`, the simple `ChatScreen`/`Composer`/`MessageBubble`, `IncomingCallDialog`, `callPath` (E1 Tasks 4–9, 12). `chat/messages.rs` overlaps M3 T3; if a task here touches it, E2 rebases after M3a.

### Findings that change the package cut

- **K16 ("mostly call-UI work") is only half true on desktop.** The Tauri app decodes every remote VP8 track natively, but `TauriVideoFrame` renders only screen shares; webcam tiles show "Video stream active", and all webcam frame sinks share the stream id `"default"` (`commands/voice.rs`). There is no local self-view on desktop. Task 12 fixes both.
- **Android has no video encoder/decoder factory set** on its `PeerConnectionFactory` and no camera code; the server SFU registers **VP8 only** (`voice/sfu.rs`), so Android must publish VP8 (Task 13).
- **Ogg/Opus uploads fail today.** `infer` detects Ogg Opus as `audio/opus`, and the allowed pairs in `chat/uploads.rs::validate_file_content` only map `audio/ogg` to `video/ogg`, so a real Ogg/Opus file claimed as `audio/ogg` is rejected. WebM is detected as `video/webm` and MP4 as `video/mp4` or `audio/m4a`. Task 3 fixes the pairs.
- **The desktop CSP blocks remote audio:** `tauri.conf.json` has `media-src 'self' blob:`, while attachment playback uses presigned `https:` S3 URLs. Task 5 adds `https:` (as `img-src` already has).
- Re-estimate: ~8.5k with the conditional Task 4, ~7.8k without (package cut said 6.5k). Still under the 9k threshold; no split needed. If one is wanted, the seam is Tasks 1–9 (voice messages) / 10–14 (video).

## Task 1 input: codec and container matrix (research done 2026-11-03)

Sources: MDN browser-compat-data, caniuse (`opus`, `webm`, `aac`), Safari 14.1 / 15 / 18.4 release notes and the WebKit "Safari 18.4" post, Chromium `mime_util_internal.cc` and `media_recorder_handler.cc`, chromestatus (MP4 MediaRecorder, Chrome 126), Firefox `MediaRecorder.cpp` and `ffvpx` codec list, WebKit `MediaRecorderPrivateGStreamer.cpp` and the WebKitGTK 2.48 release notes, GStreamer plugin docs, Android "Supported media formats" and `MediaRecorder` reference plus AOSP extractor/writer sources, AndroidX Media3 supported formats, Tauri AppImage docs, wry changelog. "Unverified" = no primary source found.

**Playback**

| Engine | Ogg/Opus | WebM/Opus | MP4/AAC |
|---|---|---|---|
| Chrome / Edge | yes | yes | yes (proprietary-codec builds; plain Chromium builds: no) |
| WebView2 (Windows desktop) | yes | yes | expected yes (Edge codebase), **unverified** in Microsoft docs |
| Firefox | yes | yes | Windows/macOS via OS decoders; **Linux needs system libavcodec** (bundled ffvpx has no AAC) |
| Safari / WKWebView (macOS desktop) | **only Safari 18.4 on macOS 15.4+** | Safari 15+ (macOS 11.3+); blob-URL playback buggy before ~17.5 | yes |
| WebKitGTK (Linux desktop) | yes (`oggdemux`, `opusdec`: gst-plugins-base) | yes (`matroskademux`: gst-plugins-good) | **needs gst-libav** (`avdec_aac`) or fdk/faad from -bad; not in a default Ubuntu desktop install |
| Android `MediaPlayer` | yes, API 23+ (AOSP OggExtractor) | yes, API 21+ | yes |
| Media3 ExoPlayer | yes, API 21+, no extension needed | yes | yes |

**Recording**

| Engine | WebM/Opus | Ogg/Opus | MP4 |
|---|---|---|---|
| Chrome / Edge / WebView2 | yes | no | Chrome 126+ (Opus in MP4; AAC only with a platform encoder) |
| Firefox | yes | yes | no |
| Safari / WKWebView | Safari 18.4+ | no | Safari 14.1+ (AAC) |
| WebKitGTK | 2.48+ **and** GStreamer ≥ 1.24.9 (not Ubuntu 22.04/24.04 stock) | no | default `audio/mp4`, needs gst-libav encoder |
| Android `MediaRecorder` | `WEBM` + `OPUS`: API 29+ by AOSP source, docs only say VP8/Vorbis (**device test**) | `OGG` + `OPUS`: API 29+ (documented) | `MPEG_4` + `AAC`: all API levels |
| Android `MediaCodec` Opus encoder | API 29+ (documented "Android 10+") | | |

Webview microphone in Tauri: WebKitGTK denies `getUserMedia` unless the app installs a permission handler (Tauri 2.12+ `on_permission_request`); WKWebView needs `NSMicrophoneUsageDescription`; WebView2 prompts. The desktop already captures the microphone natively for voice, so a native recorder avoids all three.

**Recommended default**

- Canonical format: **WebM/Opus, mono, 48 kHz, 32 kbit/s VBR, 20 ms frames** (`audio/webm`). It is the only format every client engine plays (gap: Safari < 15 / macOS < 11.3).
- Recorders:
  - Web: `MediaRecorder` with the first supported of `audio/webm;codecs=opus`, `audio/mp4;codecs=mp4a.40.2`, `audio/mp4`. Firefox and Chromium give WebM/Opus; Safari ≥ 18.4 WebM/Opus; Safari 14.1–18.3 MP4/AAC.
  - Desktop, all three OSes: **native** recorder writing WebM/Opus (Task 5).
  - Android, both apps: API ≥ 29 WebM/Opus (branch per D2), API 26–28 MP4/AAC (48 kHz mono, 64 kbit/s).
- Players: HTML `<audio>` with a presigned `https:` URL (never a blob URL, avoiding the old Safari blob bug) on web and desktop; Android `MediaPlayer` on a cached local file. No new player dependency.
- Ogg/Opus is accepted by the server (spec) but no Kaiku client records it.

- UI contrast (CLAUDE.md): readable text `text-text-primary` / `text-text-secondary` (Android `onSurface` / `onSurfaceVariant`); waveform bars and accent colours are decorative only; never `text-accent-primary` on `bg-accent-primary/*`; no `opacity` below 50 % on readable text.
- Accessibility (spec): no gesture-only action — recording is tap to start, then explicit Send / Cancel buttons (no hold-to-record); play buttons and camera buttons have labels; simple app sizes from `SimpleSizes` (64 dp primary, 96 dp call buttons).
- Android i18n per `mobile/android/AGENTS.md` and the E1 string-placement rule (simple-only strings in `src/simple/res`); web i18n via `client/src/i18n/en/*.ts` + `de.json`, `bun run i18n:check`.
- Wire fields `snake_case`; public repo: no private hostnames, IPs or secrets; `CHANGELOG.md` entry per user-visible change; commits `type(scope): subject` with the `Co-Authored-By` trailer; migrations get their timestamp at merge.
- Video: 1:1 only (DM with exactly two participants); group video is a non-goal; camera tier "medium" = 640×480, 30 fps, 500 kbit/s VP8 (same as the desktop `QualityParams::from_webcam_tier("medium")`).

## Review Focus

1. **A voice message recorded on one platform must play on every other.** If a player cannot decode it, the user sees "can't be played here" with a download button, never a silent dead control. Pinned in Tasks 7 and 9 (player error-state tests), and by the fixture files from Task 1 in the Task 3 server tests.
2. **Recording gets interrupted.** Covered cases: permission denied; recording started during a voice call (the mic button is disabled while in a call); the app is backgrounded or a phone call comes in on Android (recording stops and the clip is kept); recordings under 1 s are discarded with a message; recordings reaching 600 s stop on their own and are kept. Pinned in Tasks 5, 6 and 8.
3. **Hostile or broken voice metadata.** Duration out of range, a waveform that is too long or not base64, a non-audio MIME type, voice combined with text content, or a MIME type carrying parameters (`audio/webm;codecs=opus`) must give 400 or be normalised, never a stored inconsistent row. Pinned in Task 3; the DB CHECK is the backstop.
4. **Camera trouble during a video call.** Covered cases: permission denied; no camera; camera already in use; the peer turns the camera off (the tile falls back to the avatar); switching front and back mid-call; the camera foreground-service type on Android 14. Pinned in Tasks 11 and 13.
5. **Video outside 1:1.** Starting or enabling video in a group DM (more than two participants) or in a text-channel group call is refused with `VIDEO_NOT_ALLOWED`, and clients hide the camera there. Guild voice-channel webcams are unchanged. Pinned in Task 10.
