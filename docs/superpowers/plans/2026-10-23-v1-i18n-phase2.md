# v1.0 i18n — Phase 2: Core Strings (desktop/web + Android) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every family-facing screen of the web/desktop and Android clients reads its text from a string catalog (~300–350 web keys, ~95 Android strings), counts and dates go through `Intl`, a German locale exists as an empty scaffold that falls back to English, and CI makes sure the catalogs stay consistent, so adding German later is a translation job with no code changes.

**Architecture:** Phase 1 (PR #661, desktop Task 1) added `client/src/i18n/{en.ts,index.ts}` (`t()`, `plural()` on `@solid-primitives/i18n`) and the `I18N_GUARDED_FILES` ESLint guard. Phase 2 does five things. It splits `en.ts` into one module per area. It adds a locale signal with per-key fallback, a lazily loaded `locales/de.json` scaffold and a language picker that only shows when a build flag is set. It adds `Intl` formatters, a `check-i18n.ts` CI script (locale key parity, unused keys, placeholders, Android parity) and stricter lint selectors. Then six batched extraction PRs, one per feature area, move the text out of the files and add each file to the guard. On Android, a small custom lint detector (`ComposeHardcodedText`) fails the build on Compose string literals, a `lint.xml` ignore list gets shorter with each batch, an empty `values-de/` scaffold is added, and two extraction PRs finish the job.

**Tech Stack:** Solid.js 1.9 + TypeScript 6 (vitest 4, `@solidjs/testing-library`, ESLint 10 flat config, jsdom 29 for XML parsing in the check script), `@solid-primitives/i18n` ^2 (MIT), `Intl.PluralRules` / `RelativeTimeFormat` / `DateTimeFormat` / `ListFormat`. Android: Kotlin 2.1, Compose BOM 2025.01.01, AGP 8.7.3 → Android Lint 31.7.3 (`com.android.tools.lint:lint-api`/`lint-checks` compileOnly, `lint-tests` test-only, all Apache-2.0).

**Spec:** `docs/superpowers/specs/2026-10-20-v1-family-release-goal-design.md` ("i18n: English for v1.0, German likely later — design for it now") · Review: `docs/reviews/2026-10-22-v1-family-release-readiness.md` (U-13, U-14, "Design inputs → i18n") · Contracts: `docs/superpowers/plans/2026-10-22-v1-family-contracts.md` (C4 is used in Tasks 4/9) · Builds on: `2026-10-22-v1-desktop-phase1.md` Task 1, 12, 13 and `2026-10-22-v1-android-phase1.md` Tasks 1–10 (PRs #660, #661, #662, #665).

## Proposed contracts (C15+, for the contracts file — not edited here)

**C15 — String keys and catalog layout (web ⇄ Android, binding for every Phase-2 stream that adds UI text, e.g. push and the before-rollout UI items).**
- Web key: `area.screen.purpose`. Segments are lower camelCase (`/^[a-z][a-zA-Z0-9]*(\.[a-z][a-zA-Z0-9]*)+$/`), one whole sentence per key, `{{name}}` placeholders, plural forms as sibling keys `….one` / `….other` (more CLDR categories can be added later, e.g. `….few`).
- The first segment is the area. Area keys live in `client/src/i18n/en/<area>.ts`, and no other file may hold keys for that area. Areas: `common, connection, time, errors, auth, qr, onboarding, home, dm, channels, chat, voice, settings, admin, notifications`. A new area means a new file plus one spread line in `en.ts`.
- Android name = `toAndroidName(webKey)`: `.` → `_` and camelCase → snake_case (`connection.retryNow` ⇄ `connection_retry_now`). When a message means the same thing on both platforms, both sides use the mirrored key. Web plurals `x.one`/`x.other` map to one Android `<plurals name="x">`. Android placeholders are `%1$s`/`%1$d`, web placeholders are `{{name}}`. Only the key is mirrored, never the placeholder syntax.
- ViewModels expose `@StringRes Int` (Phase 1 pattern). They never expose English text or server `message` strings.

**C16 — Structured HTTP errors (desktop-internal, used by every web batch).** `HttpError` in `client/src/lib/tauri/common.ts` gets `readonly code?: string`, filled from the server error body's `error` field (`INVALID_CREDENTIALS`, `USER_EXISTS`, `REGISTRATION_DISABLED`, `VALIDATION_ERROR`, `RATE_LIMITED`, …). The constructor becomes `(status, message, code?)`, so existing calls stay valid. UI code turns errors into text only through `errorText()` (Task 4) and never shows `err.message` directly. The one exception: `VALIDATION_ERROR` messages are shown verbatim, since the server is English-only (post-1.0: server validation codes).

**C17 — Locale folders are empty or complete (Android, and web once enabled).** `values-<lang>/strings.xml` either has no entries or translates every string and plural in `values/`. Android picks it from the system language with no app-side switch, so a partial folder would show mixed languages. The web `locales/<lang>.json` may be partial (empty values fall back per key) because the language picker is hidden behind `VITE_FEATURE_LOCALE_SWITCH`. A language may only be listed in Android's `locales_config.xml` or turned on for the web picker once it is complete.

## Global Constraints

- Repo rules (`CLAUDE.md`): never commit to `main`. Branches are `feature/…`/`fix/…`/`refactor/…`, one worktree per task, squash-merge. Commit format `type(scope): subject`, ≤ 72 chars, imperative. Scope is always `client` for this plan (Android included), `infra` for CI-only changes.
- English copy stays **byte-identical** when moved into the catalog, except where a task lists a copy fix (plural grammar, "server" instead of "guild"). Unit tests and Playwright specs that match text (e.g. `e2e/auth.spec.ts` `text=Invalid`, `placeholder="Enter your username"`) must keep passing unchanged.
- Whole sentences only. No `{" "}` joins of sentence fragments, no `"s"` ternaries, no string concatenation around `t()`. If a sentence wraps an inline element (a link or a `<strong>` name), split it into whole-sentence keys, or pass the name as a placeholder.
- `t()` takes a literal key or a value typed `MessageKey`, e.g. from a `Record<Enum, MessageKey>` map with literal entries. Template-literal keys are forbidden, because the unused-key check finds keys by their literal text.
- Every file a batch migrates is added to `I18N_GUARDED_FILES` in `client/eslint.i18n.mjs` in the same PR. Large files that are only partly in scope are not guarded, and the plan names them.
- Date and time **numbers** (clock time, day/month order) follow the system region unless the user explicitly picked a language. **Words** (relative time, "Yesterday", list joins, plurals) follow the UI language. Never hardcode `"en-US"`.
- Pre-push gates for web tasks: `cd client && bunx tsc --noEmit && bun run lint && bun run i18n:check && bun run test:run`. Android: CI is the source of truth because the dev host has no JDK. Push the branch and require the `Android Build` job (`assembleDebug`, `lintDebug`, `:lint-rules:test`) to be green. Unit tests stay `continue-on-error` (R-14, release stream). Count them as passing only when the CI log shows them passed.
- CHANGELOG (`[Unreleased]`, Keep a Changelog 1.1.0) only for changes users can see: plural/grammar fixes, clearer error texts. Pure extraction, the hidden picker and lint changes get no entry.
- License policy (`CLAUDE.md`): the only new dependencies are the Android Lint artifacts (Apache-2.0, compileOnly/test, not shipped in the APK).
- No new hardcoded user-facing strings anywhere a task touches (spec). Contrast rules (`CLAUDE.md` "UI Contrast Rules") apply to the language picker.
- Model per task: Sonnet 5.5 for mechanical extraction and scripts, Opus 5.5 for runtime/design and the lint detector. Each task review uses Sonnet (Fable for Task 1 and 10) plus one external model (Gemini 4 Argon preferred for string sweeps, otherwise Codex), per `docs/developer-guide/agents/multi-model-workflow.md`.

## Review Focus

1. **German family member's PC, app language left at default** → clock times must stay 24 h and dates `23. Okt.`-style as they are today, not switch to `02:30 PM`, because "English UI" must not mean "US formats". Pinned by `formatTime follows the system region when no language was chosen` (Task 2).
2. **German translation started but incomplete** → web: the picker stays hidden and missing keys fall back to English per key. Android: a partly filled `values-de` would show mixed languages on every German phone, so CI rejects it. Pinned by `t falls back to English for empty de values` (Task 1) and `android locale folder must be empty or complete` (Task 3).
3. **Stored language is no longer allowed** (flag turned off in a later build, or the stored value is junk like `"xx"` or the JSON is missing) → app starts in English, never with raw keys or a blank screen. Pinned by `initLocale ignores the stored choice when the switch is disabled` and `initLocale falls back to en for an unknown or unloadable locale` (Task 1).
4. **Server error with an unknown code, or no body at all (proxy 502, offline)** → the user sees the task's fallback sentence, never `HTTP 502: Bad Gateway` or a raw code. Pinned by `errorText uses the fallback for unknown codes and bodiless errors` and `errorText maps fetch TypeError to errors.network` (Task 4).
5. **Text that lint cannot see** (strings returned from `createMemo`/helper functions, ternaries inside `class=`) → extraction must not miss the first kind, and lint must not report the second. Pinned by the selector tests `does not flag class ternaries or t() args` and `flags literal ternaries in children and toast titles` (Task 3) and by each batch's residual grep step.
