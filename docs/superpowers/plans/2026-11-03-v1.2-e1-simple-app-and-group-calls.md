# v1.2 E1: Kaiku Einfach (simple Android app) and group calls Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship a second Android app, "Kaiku Einfach" (chats, chat with photos, full-screen calls, setup-code-only start), built from the same codebase as the full app, plus WhatsApp-style group calls that ring the members of a guild text channel on every client.

**Architecture:** Android product flavors `full` and `simple` on one `:app` module. Shared code (data, push, voice, calls, approvals, setup, theme) stays in `src/main`; today's screens move to `src/full` with `git mv`; the new UI lives in `src/simple` under the package `io.wolftown.kaiku.simple`. A Hilt-bound `FlavorUi` seam lets the shared `MainActivity` host either app. The Android app gets the DM call stack it lacks today (answering in-app, full-screen incoming call, in-call screen) in shared code, so both apps share it. On the server, the DM call service is generalised to a call *scope* (`dm` | `group`); a group call lives on a guild text channel, rings members with `VIEW_CHANNEL` + `VOICE_CONNECT` (capped), and uses the text channel's id as the voice room.

**Tech Stack:** Kotlin 2.1, Jetpack Compose (BOM 2025.01.01), Hilt 2.54, stream-webrtc-android 1.3.0, Robolectric (new, test only); Rust/axum server with Valkey Streams call state; Solid.js web + Tauri 2 desktop.

**Spec:** `docs/superpowers/specs/2026-11-02-phone-key-login-and-simple-app-design.md`, Part A ("Decisions 2026-11-03" override the rest). Package cut (coordinator's working notes, 2026-11-03): sections E1 in 2.2, lanes 2.3, hotspots 2.4, K16 in 1.11.

**Split point:** Tasks 1–10 are **E1a** (simple app, DM calls on Android). Tasks 11–14 are **E1b** (group calls). E1a merges and ships on its own; E1b stacks on E1a. Task 10 is gated on open question Q1.

### Findings that change the package cut's estimate

- **Android cannot answer calls today.** The C20 call wake only posts a heads-up "is calling you – open Kaiku on the PC"; there is no call REST client, no call WS event parsing, no accept/decline, no in-call screen (`push/CallWakeProcessor.kt`, `push/NotificationPresenter.kt::buildCall`, `data/ws/ServerEvent.kt`). E1a builds that stack (Tasks 4–6). Re-estimate: E1a ~7k, E1b ~2.5k, plus rename-only moves. E1 as one PR is ~9.5k, over the 9k threshold, so the E1a/E1b split is recommended.
- **The web/desktop client only shows incoming calls inside the open DM** (`components/call/CallBanner.tsx` in `DMConversation.tsx`). Group calls need a global incoming-call dialog (Task 12), which DM calls also use.
- **No launcher icon exists** (no `mipmap` resources, no `android:icon`); Task 2 adds one for both apps.
- **`UnusedResources` is a lint error** (`app/lint.xml`), and `bun run i18n:check` reads only `src/main/res`. Task 2 handles flavor-only strings.

## Global Constraints

- Android i18n (`mobile/android/AGENTS.md`): all UI text in `strings.xml`; names are `toAndroidName(webKey)` where a web key exists; placeholders `%1$s`/`%1$d`; ViewModels expose `@StringRes Int`, never English text or server `message` strings; a `values-<lang>` folder is empty or complete (C17). German is the practical first language of the simple app, but strings still go through resources.
- UI contrast (CLAUDE.md, applied to Compose tokens): readable text uses `onBackground`/`onSurface` (= `text-primary`, ≥ 7:1 on the background); secondary text uses `onSurfaceVariant` (= `text-secondary`, ≥ 4.5:1 on `surface`); accent colours (`primary`, `error`, `tertiary`) only for decorative indicators and icons, never for text that must be read; never `primary` text on `primaryContainer`; no alpha below 0.5 on readable text.
- Accessibility (spec, a requirement): simple-app primary actions ≥ 64 dp touch target, other actions ≥ 56 dp, incoming-call accept/decline ≥ 96 dp; body text ≥ 20 sp, titles ≥ 24 sp, respecting the system font scale; every action has a visible label or `contentDescription`; no action is reachable only by a gesture (swipe, long-press, double-tap).
- Wire format fields are `snake_case` (CLAUDE.md naming convention); every call event keeps `call_id`.
- Public repository: no private hostnames, IPs or secrets in code, docs, tests or PRs.
- `CHANGELOG.md` `[Unreleased]` entry for every user-visible change, written from the user's view.
- Commits: `type(scope): subject`, ≤ 72 chars, imperative; trailer `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Quality gates per task: server `cargo test` + `cargo fmt --check` + `SQLX_OFFLINE=true cargo clippy -- -D warnings` (commit new `.sqlx/*.json`); client `bun run test:run` + `bun run i18n:check`; Android per CI matrix in Task 1.
- Merge: v1.2 PRs may be built early but stay open until the v1.0 tag, unless the maintainer cuts a release branch (spec "Sequencing", Q5). New migrations get their timestamp at merge.

## Review Focus

1. **Both apps on one phone, same account.** OIDC callback and App Link intent filters exist only in the full app, so a browser redirect never opens a chooser; both apps ring for a call; answering or declining on one device stops the ringing on every other device of that user. Pinned in Task 3 (merged-manifest check) and Task 4 (`handled` wake).
2. **Incoming call while locked or with the process dead.** The ring comes only from the push wake; the full-screen UI must show over the lock screen. If `canUseFullScreenIntent()` is false the heads-up still carries Accept/Decline. Accept must be an *activity* PendingIntent (Android 14 forbids starting a microphone foreground service from the background). Pinned in Task 5.
3. **Group call in a big or private channel.** Only members with `VIEW_CHANNEL` and `VOICE_CONNECT`, not blocked either way, not bots or the system account, at most 25, are rung; an un-rung member with access can still join; rung members stop ringing after `ring_secs` even while the call is active. Pinned in Task 11.
4. **The call changes while the incoming screen is up.** Caller cancels, call times out, or (group) someone else answers: the screen closes or keeps ringing as the rules say, and the ringtone always stops with the screen. Pinned in Tasks 4 and 5.
5. **Large font scale and TalkBack.** At font scale 2.0 the simple screens keep every primary action visible and ≥ 64 dp, and every action has a label. Pinned in Tasks 7–9 (Robolectric Compose tests).
