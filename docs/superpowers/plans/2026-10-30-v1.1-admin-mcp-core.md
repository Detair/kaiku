# v1.1 Admin MCP Core (Plan 1 of 3) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A system admin can create a scoped agent token in User Settings and run every `read`/`write`-tier admin and guild-management action of a Kaiku server through a built-in `/mcp` endpoint. The endpoint uses the same code path, permission checks and audit trail as the admin panel. `elevated`/`destructive` tools are listed but answer "not available until approvals ship".

**Architecture:** Spec phases v1.1-a and v1.1-b.
- **Phase a, tasks 1–10.** Closes the admin parity gaps (system admins, server settings, runtime optional features). Makes every admin mutation write its audit row inside the mutation's transaction. Adds `agent_tokens` as a third credential kind: `require_auth` authenticates it, and a default-deny gate inside `require_auth` admits it only on routes declared in a route-policy table. That table is built from the `x-mcp` extensions on the utoipa operations.
- **Phase b, tasks 11–15.** Adds `/mcp` (hand-written JSON-RPC over Streamable HTTP, three protocol revisions). It turns every `x-mcp` operation into a tool and executes a tool call as a child request through the finished, fully layered `Router` (`tower::ServiceExt::oneshot`), so auth, scopes, elevation, permissions, rate limits and audit run unchanged.
- **CI guard.** A source-scanning test keeps routes, OpenAPI operations and tools in parity.

**Tech Stack:** Rust 1.95, axum 0.8, tower 0.5, tower-http 0.6, sqlx 0.9 (runtime queries), fred 10 (Valkey), utoipa 5.4 (`extensions(...)`), sha2 0.10, `subtle` 2.6 (new direct dep, already in `Cargo.lock`, BSD-3-Clause), reqwest (shim). Client: Solid.js, vitest, UnoCSS, lucide-solid.

**Spec:** `docs/superpowers/specs/2026-10-30-mcp-admin-and-agent-bots-design.md` (sections 3.1 rows 1–3, 4.1, 4.2, 4.3, 4.5, 4.6, 6 phases a+b, 8). Plans 2 (approvals, v1.1-c) and 3 (agent bots, v1.1-d/e) build on the **Interfaces for plans 2 and 3** section below.

**I6 — `agent_tokens` schema and elevation storage** (migration `server/migrations/20261120000000_agent_tokens.sql`)
```sql
CREATE TABLE agent_tokens (
    id            UUID PRIMARY KEY,                 -- also the <id> in kaiku_at_<id>_<secret>
    owner_id      UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    name          VARCHAR(100) NOT NULL,
    secret_hash   BYTEA NOT NULL CHECK (octet_length(secret_hash) = 32),  -- SHA-256(secret)
    scopes        TEXT[] NOT NULL CHECK (cardinality(scopes) > 0 AND scopes <@
                  ARRAY['admin:read','admin:write','admin:elevated','guild:manage']::text[]),
    created_at    TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    expires_at    TIMESTAMPTZ NOT NULL,
    last_used_at  TIMESTAMPTZ,
    last_used_ip  INET,
    revoked_at    TIMESTAMPTZ,
    revoked_by    UUID REFERENCES users(id) ON DELETE SET NULL,
    revoke_reason VARCHAR(32) CHECK (revoke_reason IN
                  ('owner','admin','self','owner_banned','admin_rights_revoked')),
    CHECK (expires_at > created_at AND expires_at <= created_at + INTERVAL '366 days'),
    CHECK ((revoked_at IS NULL) = (revoke_reason IS NULL))
);
CREATE INDEX idx_agent_tokens_owner_active ON agent_tokens(owner_id) WHERE revoked_at IS NULL;

ALTER TABLE elevated_sessions ALTER COLUMN session_id DROP NOT NULL;
ALTER TABLE elevated_sessions ADD COLUMN agent_token_id UUID
    REFERENCES agent_tokens(id) ON DELETE CASCADE;
ALTER TABLE elevated_sessions ADD CONSTRAINT elevated_sessions_one_owner
    CHECK ((session_id IS NULL) <> (agent_token_id IS NULL));
ALTER TABLE elevated_sessions ADD CONSTRAINT elevated_sessions_agent_token_id_key UNIQUE (agent_token_id);
-- existing UNIQUE(session_id) stays: NULLs are distinct, so both act as the spec's
-- partial unique indexes and `ON CONFLICT (session_id)` keeps working.
```

## Global Constraints

- Maintainer decisions (spec §8, fixed): agent-token elevation window **10 minutes**. Approvals for `elevated`/`destructive` are **a notification on mobile or desktop that is simply confirmed**; "A password never counts". v1.1 ships the admin MCP **for system admins first**. **Destructive actions only from the phone** (on by default). Plan 1 implements none of the approval mechanics, but it must not add any path that executes `elevated`/`destructive` work for an agent token.
- Spec 4.3 (verbatim): format `kaiku_at_<id>_<secret>`, "the secret is 256 bits of CSPRNG output"; "only `SHA-256(secret)` is stored, looked up by id and compared in constant time"; "The token is shown once"; "`last_used_at` and IP are written at most once per minute per token"; expiry "default 90 days, maximum 1 year".
- Spec 4.3: "**Default deny.** … rejects the `AgentToken` kind with 403 on every route that does not declare a scope requirement". "A token never exceeds its owner's rights; scopes only narrow them."
- Spec 4.2: tool calls go through "`tower::ServiceExt::oneshot` on the same `Router` the listener serves, not on a sub-router". Requirements:
  - copy `ConnectInfo<SocketAddr>` **and** `X-Forwarded-For`/`X-Real-IP`;
  - child id `x-request-id: <mcp-id>/<n>`;
  - marker extension; refuse `/mcp` children and depth > 1;
  - strip `Accept-Encoding`;
  - body limits on the outer and every child request.
- Spec 4.5 (verbatim): "Every admin mutation writes its audit row **in the same transaction as the mutation, before commit**"; failed post-commit side effects "add a second audit row `<action>.failed`"; "No path reports success without a committed audit record."
- Spec 4.1: built into the server at `/mcp`. Streamable HTTP. "the newest published revision at build time (2026-07-28 when written: no GET stream, no protocol sessions), **plus** the 2025-06-18/2025-11-25 revisions with `Mcp-Session-Id`". "requests with an unexpected `Origin` are rejected and the protocol version is validated". SSE "no buffering, keep-alive, with timeouts below the reverse proxy's".
- No new crates except `subtle = "2"` (direct use of an existing transitive dep). `cargo deny check` must stay green. No GPL/AGPL/LGPL.
- Server gates per task: `cargo nextest run -p vc-server` (dev stack via `make docker-up`), `cargo fmt --check`, `SQLX_OFFLINE=true cargo clippy -p vc-server -- -D warnings`.
  Use runtime `sqlx::query`/`query_as` like `admin/queries.rs`. If a task adds a `query!` macro, run `cargo sqlx prepare --workspace -- --all-targets` and commit `.sqlx/*.json`.
- Client gates: `cd client && bun run test:run && bun run lint` (if `lint` exists), plus the existing `tsc` check used in CI. i18n: every new string goes in `client/src/i18n/en/*.ts` **and** `client/src/i18n/locales/de.json`. ## Review Focus

1. **An agent token reaching a route that authenticates itself instead of using `require_auth`** (`/ws`, `/api/gateway/bot`, `/api/messages/{id}/download?token=`, `/api/files/{*key}`). Expected: refused, never 2xx. Test: `agent_token_refused_on_self_authenticating_routes` (Task 8).
2. **A path template that differs between OpenAPI and the mounted route**: `{id}` vs `{guild_id}`, or a nested `"/"` route such as `/api/guilds/{id}/filters`. The gate would then deny the tool at runtime even though it is listed. Expected: CI fails; a real nested call succeeds. Tests: `every_x_mcp_operation_is_mounted` (Task 6) and `nested_filter_route_tool_call_succeeds` (Task 12).
3. **A revoked token still accepted**: a failed Valkey invalidation, a revocation between two requests, or a token whose owner was banned or lost admin rights. Expected: the next request is rejected (401), because token validity is read from Postgres on every request and never cached. Tests: `revoked_token_rejected_without_cache_invalidation` (Task 8), `revocation_races_inflight_request`, `owner_ban_revokes_tokens` and `admin_revoke_revokes_tokens` (Task 9).
4. **Tool arguments that try to retarget the child request**: a path parameter of `../users/x/ban`, `a/b`, `?x=1` or `%2F`, or an unknown extra argument. Expected: path segments are percent-encoded, unknown arguments are rejected, the child path always equals the template. Test: `path_params_cannot_traverse_or_inject_query` (Task 12).
5. **Stored optional features above a lowered env ceiling after restart.** Example: the DB says forum on, then the operator removes `forum` from `KAIKU_OPTIONAL_FEATURES`. Expected: effective = stored ∩ env, the admin UI shows forum as "not permitted by server configuration", and the stored value is not rewritten. Test: `stored_features_clamped_by_lower_env_ceiling` (Task 4).

## Decisions this plan settles (spec left them open or ambiguous)

These are recorded here so that reviewers of plans 2 and 3 see them:

1. **JSON-RPC layer.** It is hand-written, not `rmcp`, because the endpoint must sit inside our axum auth stack per request and serve a stateless revision next to two session revisions. It also avoids a new dependency and its license review.
2. **Default-deny location.** The gate lives inside `authenticate()` (shared by `require_auth` and `require_auth_allow_password_change`), keyed on `MatchedPath` + method, so no router can forget it.
3. **Scope hierarchy.** `admin:elevated ⊇ admin:write ⊇ admin:read`. `guild:manage` is independent, and `/api/pages*` counts as an admin area.
4. **Token creation** requires an elevated admin session.
5. **Default tier for non-admin management mutations** is `write`. Channel delete is `destructive`. Role create/update and kick are `elevated` (the highest tier wins; per-request tiering is not possible statically).
6. **Unique constraints.** `UNIQUE(session_id)` stays as it is, and `UNIQUE(agent_token_id)` is added. These replace the spec's "partial unique indexes" with identical semantics.
7. **`tools/list` is filtered by the token's scopes.**
8. **Untrusted fields.** They are auto-derived from response schemas by field name and wrapped in place.
9. **`/mcp` and session JWTs.** `/mcp` refuses session JWTs. The MCP limits are 60 calls/min and 10 privileged calls/min per token.
10. **Runtime features.** A stored `null` means "env ceiling". The scheduler always runs and checks the flag on each tick.
11. **Shim location.** `kaiku-mcp` is a second binary target of `vc-server`.
12. **Streams of a revoked owner.** "Closes their streams" (spec 4.3) needs no extra code in plan 1. `/mcp` has no long-lived streams: GET is 405 and an SSE response lives for at most one tool call. Every request re-authenticates the token, so the call after a revocation fails.
13. **Revocation is immediate; token validity is never cached** (coordinator, after external review). Every agent-token request does one PK lookup that already filters `revoked_at IS NULL AND expires_at > now()`. Valkey may hold only the elevation status, which revocation and "end admin unlock" delete, and `find_token_elevation` re-checks Postgres anyway. There is no 60-second token cache.
14. **Admin token management is session-only.** GET/DELETE `/api/admin/agent-tokens*` carry no `x-mcp` extension, so the default-deny gate rejects agent tokens there. `DELETE /api/agent-tokens/self` is the only agent-callable token route.
15. **One cleanup function for every revocation.** `revoke_tx` and `revoke_all_for_owner_tx` both call `revoke_token_cleanup_tx` per token; plan 2 hooks the approval expiry into that function.
16. **An elevation window can be ended early** by the token owner (`DELETE /api/agent-tokens/{id}/elevation`) or any system admin (`DELETE /api/admin/agent-tokens/{id}/elevation`), both session-only.
